GET/api/v1/updates

Read autoupdate status

Read the status file last written by the systemd autoupdator, and will not trigger a download, restart, or upgrade from the management API. This is how the console displays a pop-up when an update downloads, completes, fails, or rolls back.

Request parameters

None.

Successful response
{"ok":true,"data":{"current_version":"0.15.0","status":{"state":"up-to-date","message":"It's now. v0.15.0."}}}

FieldsAnnotations

status.stateup-to-date,downloading,updated,deferred,failed,rolled-back or unknown.
status.messageLast update instructions that can be displayed directly to the administrator.

PUT/api/v1/rules/{id}

Modify or suspend rules

Completely replaces the specified host route. The path ID is the authoritative value, and the ID in the request body will be overwritten by the path value. Modifying the host, backend, health check, proxy Protocol, motd, whitelist, handshake Host override, Crossplay allow state or enable state will overload the single entry routing table. When Global Crossplay is enabled, it is not possible for its current Java address to lose matching allowed routes.

Path Parameters
idRule One ID.
Request

Same as New Rule.

Successful response

200,data For updated rules.

Error Code

400:Rule Does Not Exist, Parameter Is Illegal, Port Binding Failure or Persistence Failure.401:Authentication Failed.
